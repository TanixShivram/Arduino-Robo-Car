Technical Design & Safety

Engineering specifications covering logic-level interfacing, control system hierarchy, and electrical integrity considerations for the 4WD platform.

⚡
Safety & Interfacing
Logic Level Shifting — 5V ↔ 3.3V

The Arduino UNO operates at 5V TTL logic, while the HC-05 Bluetooth module utilises a 3.3V CMOS logic level on its RXD input. Directly driving a 3.3V-rated input with a 5V signal exceeds the absolute maximum voltage rating of the HC-05 transceiver IC and may result in accelerated degradation or permanent damage to the module.

A passive resistive voltage divider shall be implemented on the Arduino TX (D1) → HC-05 RXD line to attenuate the 5V output to a 3.3V-compatible level. The recommended configuration utilises a 1kΩ series resistor (R1) and a 2kΩ shunt resistor (R2) to ground, yielding an output of approximately 3.33V under the voltage divider equation:

⚠️
Implementation Note: The HC-05 TXD → Arduino RX (D0) line does not require level shifting. The HC-05 TXD output at 3.3V exceeds the Arduino's minimum HIGH threshold of 3.0V (at VCC = 5V), and is therefore recognised as a valid logic-high without additional circuitry.
🧠
Control Logic
Command Hierarchy & Safety Override Architecture

The system operates under a dual-mode control architecture — Manual Bluetooth Control and Autonomous Self-Driving — toggled at runtime via the 'U' Bluetooth command. Within both modes, a strict priority-based command hierarchy governs actuator output to ensure safe operation.

Priority Hierarchy (Descending Precedence):

  • Obstacle Detection Override (HC-SR04) — The ultrasonic sensor constitutes an interrupt-level safety mechanism. When an object is detected within the 20 cm threshold (manual mode) or 25 cm threshold (autonomous mode), the system immediately issues a stopCar() command, overriding all pending motion directives. This safety layer takes absolute precedence over any Bluetooth-originated input, ensuring collision avoidance regardless of operator commands.
  • Mode Arbiter (Manual / Auto Toggle) — The 'U' command acts as a system-level mode switch. Upon transition, all motor outputs are zeroed and the servo is re-centred to 90° before the new mode's control loop assumes authority. This prevents residual state from one mode from propagating into the other.
  • Operator Commands (Bluetooth App) — Standard directional inputs (F, B, L, R, S) and speed mode selectors (E, N, X) from the Arduino Bluetooth Controller application are processed only after the higher-priority safety and mode layers have been evaluated. In manual mode, forward motion commands are suppressed if the obstacle flag is active.
ℹ️
Operational Behaviour: In manual mode, the ultrasonic override can be independently enabled or disabled via the 'T' Bluetooth command. When disabled, the operator assumes full responsibility for obstacle avoidance. In autonomous mode, the HC-SR04 is always active and controls the servo sweep for directional path assessment.
🔌
Electrical Design
Common Grounding & Signal Integrity

Reliable serial communication between the Arduino UNO and the HC-05 Bluetooth module is critically dependent upon maintaining a common ground reference across all interconnected subsystems. Ground potential differences between independently powered modules introduce voltage offsets on the UART data lines, resulting in bit-level misinterpretation, framing errors, or complete communication failure.

⚠️
Critical Design Constraint: The L298N motor driver ground, Arduino ground, and HC-05 Bluetooth module ground must all terminate at the same electrical reference point. Failure to establish common grounding will result in undefined UART logic levels on the D0/D1 serial lines and may cause intermittent Bluetooth command loss, erratic motor behaviour, or complete system malfunction. The breadboard GND rail serves as the designated star-ground node for this design.
